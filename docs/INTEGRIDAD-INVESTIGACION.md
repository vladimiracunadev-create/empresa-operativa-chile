# Integridad, fraude y respuesta institucional

**Fecha de verificación normativa y de fuentes: 22 de septiembre de 2026.**

Este material enseña a reconocer señales, preservar evidencia, investigar con independencia y corregir controles. No diagnostica delitos ni atribuye responsabilidad personal. Una anomalía abre una pregunta; no prueba por sí sola intención, autoría ni culpabilidad.

## El modelo completo

```text
DOCUMENTO → OPERACIÓN → REGISTRO → BANCO → IMPUESTO → CONTROL
          → ALERTA → INVESTIGACIÓN → RESPONSABILIDAD → REMEDIACIÓN
```

Cada eslabón debe responder cuatro preguntas: qué ocurrió, quién actuó en qué función, qué evidencia quedó y quién revisó la excepción. Una contabilidad que cuadra puede seguir ocultando una operación inexistente, una contraparte relacionada no declarada o evidencia creada después del hecho.

## Clasificar antes de concluir

| Concepto | Pregunta mínima | Evidencia que suele ser necesaria |
|---|---|---|
| Error | ¿Hubo una equivocación verificable sin evidencia de intención? | versión original, corrección, fecha, revisión y recurrencia |
| Negligencia | ¿Se omitió un deber de cuidado aplicable? | deber documentado, competencia, advertencias y conducta esperable |
| Mala gestión | ¿Falló el diseño, la capacidad o la supervisión? | políticas, recursos, indicadores, actas y decisiones |
| Incumplimiento | ¿Se apartó la conducta de una obligación concreta? | norma o política vigente, alcance, hecho y responsable funcional |
| Conflicto de interés | ¿Un interés secundario podía interferir con el deber? | declaración, vínculo, participación en la decisión y mitigación |
| Elusión | ¿Se buscó un resultado tributario mediante actos cuya calificación exige análisis jurídico? | contratos, sustancia, propósito, norma aplicable y asesoría especializada |
| Evasión | ¿Se ocultó o alteró materia imponible incumpliendo la ley? | declaraciones, registros, flujos y prueba de conducta; exige calificación competente |
| Fraude | ¿Hubo engaño deliberado para obtener un beneficio o causar perjuicio? | representación falsa, intención, beneficio, perjuicio y nexo |
| Delito tributario | ¿Los hechos satisfacen un tipo penal tributario? | elementos del tipo, dolo cuando corresponda y decisión judicial |
| Cohecho | ¿Hubo ofrecimiento, solicitud o aceptación de un beneficio ligado a una función? | comunicaciones, beneficio, competencia, acto u omisión y decisión judicial |
| Corrupción | ¿Se abusó de poder o función para beneficio indebido? | función, deber, beneficio, interferencia y atribución respaldada |
| Impunidad | ¿Un hecho atribuible quedó sin una respuesta efectiva por fallas de la cadena? | estado procesal, competencias, decisiones, plazos y causas documentadas |

No toda irregularidad escala hacia la fila siguiente. La clasificación debe indicar el estándar aplicado, la evidencia disponible, lo que falta y quién tiene competencia para decidir.

## Documentos tributarios y sustancia económica

Un DTE auténtico acredita que se emitió un documento; no demuestra por sí solo que la operación subyacente existió, que correspondía al giro, que el bien o servicio se recibió o que el crédito fiscal procede.

### Señales que requieren revisión

- descripción genérica que no permite identificar entregable, período o unidad;
- proveedor sin capacidad observable para prestar el servicio facturado;
- fecha del contrato, informe o aceptación posterior al pago o al cierre;
- monto redondo, repetido o fraccionado alrededor de un umbral de aprobación;
- DTE que aparece en RCV, pero no tiene orden, recepción ni flujo bancario coherente;
- pago a una cuenta distinta de la contraparte contractual;
- proveedor, beneficiario, aprobador o intermediario con vínculos no declarados;
- notas de crédito tardías, reversos o cambios después del cierre;
- evidencia creada por la misma persona que solicita, aprueba y acredita la recepción;
- crédito fiscal o gasto usado pese a una alerta abierta y sin excepción aprobada.

Estas señales son **red flags**. Se combinan para priorizar revisión; no autorizan a etiquetar una operación o persona como fraudulenta.

### Prueba defensiva de cinco vías

| Fuente | Pregunta |
|---|---|
| Documento | ¿El DTE, contrato y orden coinciden en identidad, fecha, monto y objeto? |
| Operación | ¿Existe evidencia independiente de entrega, recepción o prestación? |
| Registro | ¿El asiento, auxiliar y corte representan el hecho en el período correcto? |
| Banco | ¿Pagador, beneficiario, monto y fecha son coherentes y explicables? |
| Impuesto | ¿RCV, F29, crédito fiscal, gasto y declaraciones reflejan la misma realidad? |

## Partes relacionadas, beneficiario final y conflictos

La relación no vuelve improcedente una operación. Aumenta la necesidad de declarar el vínculo, justificar condiciones, separar aprobación y conservar evidencia de sustancia y valor. El control debe registrar:

```text
contraparte → vínculo conocido → beneficiario final cuando corresponda
→ conflicto declarado → abstención/mitigación → aprobación independiente
```

La ausencia de declaración es una brecha de control. Determinar simulación, fraude o delito requiere evidencia adicional y una instancia competente.

## Diseño de control verificable

Todo riesgo debe aterrizar en una ficha operable:

| Campo | Ejemplo defensivo |
|---|---|
| Objetivo | Registrar sólo compras con operación y recepción demostrables |
| Riesgo | Usar DTE válido para respaldar una operación inexistente |
| Control | Cruce DTE–orden–recepción–banco–RCV antes de usar crédito fiscal |
| Dueño | Finanzas, separado de solicitud y pago |
| Evidencia | reporte de excepciones, revisión nominativa y decisión |
| Frecuencia | por transacción y revisión semanal de acumulados |
| Umbral | toda falta de recepción; concentración por monto o contraparte |
| Excepción | motivo, duración, aprobador independiente y vencimiento |
| Escalamiento | Compliance/Internal Audit/Board según materialidad y conflicto |
| Remediación | corregir dato y causa; ajustar permisos, flujo y monitoreo |
| Verificación | muestra posterior, resultado, fecha y revisor independiente |

Una excepción sin dueño ni vencimiento se convierte en una autorización permanente. Un control automatizado sin monitoreo puede fallar en silencio.

## Segregación de funciones

```text
create → request → validate → approve → execute → record → reconcile → audit
```

La incompatibilidad no depende sólo del cargo. También importa quién controla credenciales, parámetros, exportaciones y evidencia. Si una persona puede ejecutar y alterar el archivo que luego concilia otra área, la segregación aparente no es efectiva.

Cuando el tamaño de la empresa impide separar todas las etapas, debe existir un control compensatorio: aprobación externa, revisión posterior independiente, límite bajo, alerta inmediata y evidencia inmutable. La limitación debe quedar declarada.

## Canal de denuncias e investigación

### Triage

1. proteger a la persona reportante y evaluar riesgo de represalia;
2. minimizar datos personales y restringir accesos;
3. preservar fuentes originales sin alterar metadatos;
4. identificar urgencia, materialidad y autoridad competente;
5. declarar conflictos antes de asignar investigador;
6. separar a quien investiga de quien decide.

### Método

```text
HECHO → EVIDENCIA → HIPÓTESIS → CONTRASTE → CONCLUSIÓN
```

Nunca:

```text
SOSPECHA → CULPABLE
```

Cada conclusión debe indicar hechos establecidos, hipótesis descartadas o abiertas, limitaciones, estándar usado y vía de revisión. La presunción de inocencia, proporcionalidad, privacidad, necesidad, derecho a revisión y cadena de custodia son controles del propio proceso investigativo.

### Cadena de custodia mínima

| Elemento | Registro mínimo |
|---|---|
| Identificación | qué archivo, documento, dispositivo o fuente se preservó |
| Origen | quién lo obtuvo y por qué vía legítima |
| Tiempo | fecha y hora, zona horaria y período cubierto |
| Integridad | original, copia de trabajo y hash cuando resulte apropiado |
| Custodia | quién tuvo acceso y para qué propósito |
| Transferencia | entrega, receptor, fecha y motivo |
| Limitación | datos faltantes, sistema no confiable o metadatos incompletos |

## Causa raíz y remediación

```text
SÍNTOMA → EVIDENCIA → CORRELACIÓN → HIPÓTESIS → CAUSA RAÍZ
→ CONTROL FALLIDO → RESPONSABILIDAD FUNCIONAL → REMEDIACIÓN → VERIFICACIÓN
```

Corregir el asiento, pagar una diferencia o despedir a una persona puede atender un efecto sin corregir el sistema. La remediación debe cubrir dato, proceso, permisos, incentivo, supervisión y monitoreo. El cierre exige una prueba posterior con muestra, período, criterio y resultado.

## Decisiones institucionales e impunidad sistémica

```text
HECHO → DETECCIÓN → FISCALIZACIÓN → INVESTIGACIÓN → DECISIÓN
→ SANCIÓN/OTRA SALIDA → RECUPERACIÓN → REMEDIACIÓN
```

La cadena puede romperse por falta de competencia, acción habilitante, recursos, independencia, trazabilidad, coordinación, evidencia, oportunidad o seguimiento. También puede terminar legítimamente mediante absolución, sobreseimiento u otra salida procesal. “No hubo condena” no prueba por sí solo encubrimiento; “hubo denuncia” tampoco prueba culpabilidad.

Para estudiar una decisión institucional, registra:

| Pregunta | Evidencia |
|---|---|
| ¿Quién tenía competencia? | ley, reglamento, delegación vigente |
| ¿Qué alternativas existían? | expediente, criterios y precedentes comparables |
| ¿Qué se decidió? | acto, resolución, querella, archivo o abstención |
| ¿Por qué? | fundamentos contemporáneos, no explicaciones reconstruidas después |
| ¿Había conflicto? | declaración, abstención y reemplazo |
| ¿Quién revisó? | control jerárquico, judicial, auditoría o directorio |
| ¿Qué consecuencia siguió? | estado procesal, recuperación y remediación |
